What and why

What is dplyr

  • dplyr is a core package of the tidyverse
  • it supports data wrangling

What is the tidyverse?

  • the tidyverse is a collection of packages supporting a shared way of doing things, which I’ll call the tidyverse approach
  • there are 9 core tidyverse packages
  • there are also numerous other packages that share the tidyverse approach

So what is the tidyverse approach?

  • the tidyverse approach involves:
    • piping everything
    • using tidyverse functions
    • avoiding dollar-sign notation
    • insisting on two-dimensional output

Insisting on two-dimensional output

  • the tidyverse approach insists on two-dimensional output

More specifically, the tidyverse users prefer a two-dimensional object class known as a tibble.

Insisting on two-dimensional output

  • for example, to find the mean level of systolic blood pressure using base R:
mean(nhanes$bpxosy1, na.rm = TRUE) 
#| [1] 122.5617
  • or, using dollar() from my baseverse package:
nhanes |> dollar(bpxosy1) |> mean(na.rm = TRUE)
#| [1] 122.5617

Insisting on two-dimensional output

  • tidyverse users would do this instead:
minidata |> summarize(mean = mean(bpxosy1, na.rm = TRUE))
#|   mean
#| 1  124
  • the result is a data frame, not a single number:
minidata |> 
  summarize(mean(bpxosy1, na.rm = TRUE)) |>
  class()
#| [1] "data.frame"

Why should I not use dplyr?

  • my opinion: dplyr and tidyverse are bloated, with a lot of functions overall, including functions that reproduce base-R functions or features
  • my opinion: the tidyverse approach is too strict
  • my opinion: the introduction of piping to base R makes dplyr and tidyverse feel even more redundant

Why should I use dplyr?

  • dplyr and the tidyverse are enormously popular
  • dplyr also includes functions and approaches that people argue to be easier to understand or easier to read than base-R equivalents
  • in some cases, dplyr or tidyverse functions can be faster than base-R equivalents

Why should I learn dplyr?

  • putting aside a base R versus tidyverse argument for now…
  • it’s good to understand at least a little bit of dplyr—even if you don’t plan on using it—because it’s so popular

Defining categorical variables

  • all of the strategies from Session 7 of A Slower Introduction to R can be combined with mutate() and piping

Labeling categorical variables

  • using factor():
nhanes <- nhanes |>
  mutate(country = factor(
    dmdborn4,
    levels = c(1, 2),
    labels = c('USA', 'Other')
  ))
  • or, using base_match() from my baseverse package:
nhanes <- nhanes |>
  mutate(country = base_match(dmdborn4, 'USA' = 1, 'Other' = 2))

Labeling categorical variables

  • country looks like this:
nhanes |> count(country)
#|   country    n
#| 1     USA 6519
#| 2   Other 1617
#| 3    <NA>   17
  • whereas dmdborn4 looks like this:
nhanes |> count(dmdborn4)
#|   dmdborn4    n
#| 1        1 6519
#| 2        2 1617
#| 3       NA   17

Categorizing continuous variables

  • using cut():
nhanes <- nhanes |>
  mutate(cholesterol = cut(
    lbxtc,
    breaks = c(0, 200, 240, Inf),
    labels = c('Desirable', 'Borderline high', 'High'),
    right = FALSE
  ))

Categorizing continuous variables

  • or, using base_when() from my baseverse package:
nhanes <- nhanes |>
  mutate(cholesterol = base_when(
    'Desirable' = (lbxtc < 200),
    'Borderline high' = (lbxtc >= 200) & (lbxtc < 240),
    'High' = (lbxtc >= 240)
  ))

Should I use dplyr and tidyverse?

Comparison

  • a summary of key dplyr functions and their base-R equivalents:
base R baseverse dplyr
subset() filter()
subset(select=) keep() select()
transform() mutate()

Comparison

  • many key functions in dplyr reproduce base-R functions
  • that being said, the dplyr equivalents may be faster or offer other improvements
  • dplyr and tidyverse overall also offer numerous other functions that some find useful or convenient

Comparison

  • for example, starts_with() can be used in select() to pick variables beginning with a pattern:
nhanes |> select(starts_with('bpxosy'))
  • a base-R approach would be:
nhanes |> subset(select=grep('^bpxosy',names(nhanes)))
  • this uses grep(), a powerful base-R function for searching for text strings
